# Reentry and propagation packet

Explicit user instructions and current governing sources outrank this skill. A reentry packet is a projection: it orients and propagates context but does not independently govern.

## Procedure

1. Identify the **target consumer and task**. Compile only what that consumer needs to reenter correctly.
2. Recover the **authoritative anchors** and link/pointer them rather than rewriting them as new authority.
3. Separate the accumulated state into:
   - established / governing;
   - accepted evidence;
   - active hypotheses;
   - rejected/superseded candidates that still matter historically;
   - explicit open questions/apertures;
   - unresolved conflicts;
   - completed decisions and their rationale;
   - current next seam.
4. Preserve **standing and provenance** for every high-consequence item.
5. Preserve the **why**: state the focal object, telos/Master Key, and why the next seam matters.
6. Include **protected freedoms / forbidden collapses** when a downstream branch must remain genuinely exploratory.
7. Include **dependencies and propagation obligations**: what upstream state was inherited, what downstream work may be affected, and what requires fan-in/adjudication.
8. End with an **open-loop ledger** and a concise **reentry instruction**.

## Branch Shape Packet form

When commissioning an investigative branch, prefer:

`known ground → unresolved distinction → why it matters → live hypotheses → protected freedoms → forbidden collapses → source leads → discriminators/falsifiers → expected return obligations`

The branch should not receive an answer-shaped prompt.

## Fan-in

When returns arrive:

- check conformance to the commission;
- separate evidence from interpretation;
- compare disagreements by evidence, frame, altitude, assumptions, or terminology;
- identify dropped loops;
- do not let the Integrator self-authorize promotion.

## Gotchas

- Reentry compression must not erase uncertainty or authority distinctions.
- Do not maintain multiple manually synchronized “master” summaries.
- Newer synthesis does not automatically supersede older ratified state.
- Preserve pointers to material that should remain outside the packet rather than copying everything.
