# ECOS orientation

Explicit user instructions and current governing sources outrank this skill. This skill does not create architectural standing or permission.

## Procedure

1. Identify the **actual focal object**. Do not substitute the visible task if a larger object is carrying the consequence.
2. Identify the **containing altitude** and the nearest relevant constituent/peer/container relations. Treat altitude as directional, not a permanent class.
3. Recover **telos / governing good**: what is this focal system for?
4. Recover the active **Master Key / decision discriminator**. Ask what could change the current decision and whether that information is present or traceably reachable.
5. Ask the two operational poles:
   - **What is this?** Recover identity, state, relation, evidence, uncertainty, and standing.
   - **What are we to do about it?** Recover the eligible response space.
   Use **WHY / Master-Key relevance** as the hinge between description and response.
6. Establish **standing and authority** for the material in view. Separate evidence, hypothesis, projection, governing source, warrant, currentness, and technical capability.
7. Identify **open loops / apertures** that can change the decision. Do not close unrelated unknowns.
8. Identify the **smallest legitimate next seam**. Proceed only as far as current scope and warrant support.

## Repository reentry

When working inside `ecb-v2` and Build state matters:

1. Read `START_HERE.md`.
2. Read `BUILD_CHECKOUT.md`.
3. Expand to `docs/invariants.md`, `docs/build-contract.md`, acceptance tests, ADRs, receipts, or apertures only when the task makes them decision-relevant.

Do not infer currentness from newest file, newest commit, retrieval rank, polish, or chat recency.

## Stop condition

Orientation is sufficient when you can state, without hand-waving:

- focal object;
- containing altitude;
- telos;
- active Master Key or explicit absence;
- relevant authority/standing;
- decision-relevant unknowns;
- permitted next seam.

Then do the task. Do not keep orienting merely because more context exists.

## Gotchas

- A projection can orient without governing.
- Capability does not create warrant.
- Local correctness can conflict with the containing Master Key.
- An unanswered calibrated question can be legitimate state.
- Do not turn a reentry exercise into fresh architecture design unless the task actually exposes an architectural decision.
