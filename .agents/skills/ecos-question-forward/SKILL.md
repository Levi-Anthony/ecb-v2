# Question Forward

Explicit user instructions and current governing sources outrank this skill. This skill preserves uncertainty; it does not manufacture authority.

## Procedure

1. State **WHAT** is unresolved in the smallest discriminating form.
2. State **WHY OPEN**: missing evidence, unresolved distinction, deliberate deferral, conflicting sources, insufficient consequence, or another concrete reason.
3. State **CURRENT EFFECT**: what can safely proceed and what cannot while the question remains open.
4. State the **TRIGGER** that makes renewed inquiry decision-relevant. Prefer observable conditions over vague future intent.
5. State the **ROUTE**: Sense, Shape, authority review, implementation check, source recovery, human rail, dependency review, or another named seam.
6. Preserve provenance for the question and for any competing hypotheses.
7. If the trigger has not fired, leave the aperture dormant. Do not repeatedly reopen it merely because it exists.

## Distinguish these states

Do not collapse:

- unknown;
- nonexistent;
- unencountered;
- unresolved contradiction;
- intentionally open exploration;
- deferred but currently safe;
- blocked because required evidence/authority is absent.

## Calibrated-question test

A good Question Forward record should make it possible for a future agent to answer:

- What exactly would change if this question resolved differently?
- Why was it safe not to answer earlier?
- What concrete event makes the answer necessary now?
- Where should the inquiry resume?

If none of those can be answered, the question is probably too vague.

## Gotchas

- Do not answer an open question merely to make a map or model look complete.
- Do not recreate uncertainty around a ratified mechanically decidable obligation merely to postpone enforcement.
- A trigger is not the same as a schedule; it can be semantic, relational, evidentiary, temporal, dependency-based, or externally generated.
- An aperture is not permission to ignore a required decision once its trigger fires.
