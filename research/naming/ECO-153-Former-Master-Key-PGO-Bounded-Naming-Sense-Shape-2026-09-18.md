# Bounded Naming Sense + Shape — former Master Key / provisional PGO

**Date:** 18 September 2026 America/Phoenix
**Standing:** Sense + Shape complete for a separately governed naming Move. No replacement designation is selected or adopted here.

## 1. SENSE — focal naming referent

The naming target is one semantic/compositional system function:

> recover, qualify, compose, and expose enough consequential information to bound and semantically close the present interpretation/action envelope without claiming global closure.

Depending on the present Move, the function may need to resolve or carry:

* focal Referent;
* purpose/telos;
* governing obligations;
* consequential frames and axioms;
* evidence/access conditions;
* authority/standing;
* intended Move/use;
* sufficiency/stopping;
* reentry conditions;
* material unresolved questions / Question Forward.

The function is compositional. One giant declaration is not required.

### Current aliases / standing

* **Master Key** — historical name; explicitly demoted from reified system usage.
* **Principal Governing Orientation (PGO)** — current provisional name only.
* **Governing Orientation** — generic descriptive phrase used in several current documents.

No one of these names is canonical by this commission.

## 2. What is *not* being named

The run must not collapse the focal function into any downstream representation or state.

Distinct neighboring referents remain:

* **Orientation Resolution** — an immutable materialized representation of the compositional function for one bounded context.
* **Orientation Scope** — a persistent scope/currentness subject.
* **Qualification** — an assessment of an exact Resolution for a declared use.
* **Current Binding / Binding Transition** — explicit currentness history.
* **Authority Decision** — independently resolved authority relevant to selecting/withdrawing a current orientation.
* **Move** — the interpretation/action being considered or undertaken.
* **Question Forward** — explicit forward structure for material unknowns.

The function may compose or resolve these; it is not identical to them.

## 3. Consequential nonexamples / false implications to reject

A candidate fails if it materially implies that the focal function:

* is one object, packet, key, document, or Artifact;
* creates authority merely by being present;
* is the Principal/authority-holder itself;
* authorizes external action/effect;
* establishes truth;
* claims global closure or exhaustive ontology;
* is merely a goal, scope statement, frame, prompt, context blob, or stopping rule;
* is identical to Orientation Resolution/current binding/qualification;
* permanently fixes all relevance;
* requires every URG capacity to be populated;
* erases unresolved questions rather than bounding/carrrying them;
* makes newest equivalent to current.

## 4. System placement

The function is a high-centrality SIGMA/ECOS orientation/governance primitive used across inquiry and action.

It is upstream of BUILD 7′ production orientation semantics but is not a database object or BUILD-specific implementation mechanism.

BUILD 7′ consumes enough of the function through a versioned interface to:

1. resolve an exact governing orientation for focal Referent + use/scope;
2. qualify that exact Resolution;
3. establish/recover scoped currentness separately;
4. detect material dependency change and route requalification.

Full URG closure is not required for this naming run.

## 5. Why name now

The architecture has sharpened enough that the old metaphor and current provisional acronym are creating avoidable continuity debt:

* historical sources still say **Master Key**;
* current semantic work often says **PGO**;
* BUILD 7′ deliberately uses more precise physical/interface nouns such as Orientation Resolution and Current Binding;
* broad implementation has not yet hardened a new production vocabulary.

This is therefore a favorable naming seam: meaning is sufficiently stable, while migration cost is still low.

# SHAPE

## 9. State effect

**Proposal only.**

The naming run may recommend a designation and interface. It may not:

* canonize/adopt the name;
* mechanically rename historical evidence;
* patch schemas/APIs/runtime;
* infer authority from recommendation;
* broad-search-and-replace the corpus.

Human/Principal ratification is a separate disposition after the return.

## 10. Required naming interfaces

The run must distinguish and propose only where useful:

1. **Formal semantic designation** — the full name for the function.
2. **Ordinary prose form** — readable in explanatory text.
3. **Compact form / abbreviation** — only if it survives qualification.
4. **Machine identifier** — only after the semantic winner is selected.
5. **Historical alias handling** — how “Master Key” and “PGO” should be interpreted during migration.

Do not invent separate strings for each interface if one designation works.

## 11. Comparison priorities

Order of importance:

1. **Semantic/structural fidelity**
2. **Avoidance of authority and artifact reification**
3. **Discriminability from neighboring orientation/currentness/authority concepts**
4. **Cold-reader legibility**
5. **Retrieval/discovery quality**
6. **Natural conversational use**
7. **Lifecycle robustness as implementations change**
8. **Memorability / human appeal**
9. **Machine-form cleanliness**

Memorability or cleverness cannot compensate for a structural failure.

## 12. Hard rejection conditions

Reject a candidate that:

* materially suggests a packet/object rather than a compositional function;
* implies it owns or manufactures Principal authority;
* implies external-action authorization;
* collapses function with Orientation Resolution, Current Binding, Qualification, Scope, or Move;
* implies exhaustive/global closure;
* is so generic that ordinary uses of the term would cause high retrieval ambiguity or false activation;
* has an inherited technical/legal meaning that materially redirects interpretation;
* requires a strained acronym expansion that changes the function;
* is pleasant only because explanatory descriptors repair a misleading core name.

Conditional candidates may survive only with an explicit descriptor if the descriptor is expected to remain on primary discovery surfaces.

## 13. Candidate-generation rule

Generate a bounded, meaningfully different set **before selecting**.

The set should explore:

* established/technical terminology where genuinely applicable;
* direct functional names;
* compact descriptive constructions;
* evocative/metaphoric names only if they do not reify;
* acronym/initialism forms only where the expansion independently fits.

Do not privilege **Master Key**, **PGO**, **Governing Orientation**, or any remembered prior candidate merely because it is incumbent.

Incumbents must be evaluated in the same matrix as new candidates.

## 14. Required adversarial tests

For strongest candidates, test at minimum:

### Reduced-context expectation

What would a competent cold reader expect the thing to do from the name alone?

### Process / artifact distinction

Can a reader distinguish:

* “resolve/use the \[function\]”
  from
* “store/fetch an Orientation Resolution”?

### Authority distinction

Does:

* “the \__\_ for this Move”
  sound like it creates authority, names the Principal, or authorizes the Move?

### Currentness distinction

Can:

* “the \__\_ changed”
  be distinguished from:
* “the current binding changed”?

### Multiple materializations

Can multiple packets/Resolutions represent or participate in the same function without the grammar becoming absurd?

### Lifecycle

Does the name still work when:

* there is no current binding;
* authority is unresolved;
* a grammar version changes;
* a prior Resolution remains historical;
* the function recursively examines an assessment of another map?

### Conversational specimens

Test forms such as:

* “What is governing this inquiry?”
* “Resolve the \__\_ before entering Shape.”
* “Under the current \__\_, this question is consequential.”
* “The \__\_ is compositional; this packet is only one materialization.”
* “The authority source changed, but the \__\_ representation did not.”
* “This Resolution is qualified but is not currently bound.”

### Collision / retrieval

Inspect current SIGMA/ECOS corpus neighbors and relevant external terms of art. Distinguish a corpus collision from a generic English collision.

### Overshoot

Literalize the strongest metaphor/term and push it beyond its intended context. Determine whether failure belongs to:

* the candidate;
* descriptor/interface;
* retrieval binding;
* or the underlying concept.

Otherwise complete the bounded naming run and stop at recommendation/proposal.
