## 1. Idealized first-class naming end state

**SHAPE DECISION.** The desired end state is a two-resolution naming interface:

> **A compact first-class proper name acts as the effortless system address; a recoverable semantic descriptor and cold definition carry the precision.**

The first-class name should be usable before a person remembers its expansion, provenance, or full semantic contract. It should work as a stable address in speech, prose, retrieval, status reporting, and cross-reference. A cold reader must nevertheless be able to traverse from that address to a descriptor and then to the full definition and provenance.

This is progressive disclosure rather than semantic outsourcing. The proper name may be partially or even substantially opaque at first encounter, but it may not misdirect the referent. The descriptor carries explicit semantic precision; it does not repair a false core identity.

The target experience is:

`proper name → semantic descriptor → cold definition → provenance / architecture`

The name should eventually behave like a native system address rather than a heading that must be re-explained on every invocation.

**SHAPE DECISION — backward derivation from that end state.** A first-class outcome therefore needs all of the following simultaneously:

* one stable proper-name identity for the focal function;
* a recoverable semantic descriptor;
* a clean boundary from procedure, materialization, currentness, authority, and action;
* routine spoken and written usability;
* discriminability in the corpus in which continuity depends on retrieval;
* resilience as the architecture grows;
* progressive disclosure for cold readers;
* room for multiplicative symbolic, disciplinary, or brand value without making such value necessary to repair semantic weakness;
* a selection process that preserves human recognition without allowing taste to override structural truth.

**INFERENCE.** This architecture best explains why SIGMA works without forcing the SIGMA mechanism. SIGMA happens to collapse proper-name, disciplinary expansion, symbolic resonance, and retrieval identity into one compact token. ECOS shows that a strong token can remain first-class even when its brand-layer expansion and deeper semantic contract are not identical.

## 2. Frozen naming-layer architecture

### Layer 1 — first-class proper name

**SHAPE DECISION — REQUIRED.** The focal function receives a compact proper-name identity if a candidate qualifies.

Its job is identity and addressability. It must remain the same referent whether the function has zero, one, or multiple current materializations. It does not become an Artifact merely because an Artifact carries a representation of it.

The proper name may be acronymic, borrowed, coined, metaphorical, opaque, or directly functional. No method family receives semantic privilege.

### Layer 2 — semantic descriptor / cold definition

**SHAPE DECISION — REQUIRED.** A cold-readable semantic descriptor travels with the name on discovery surfaces and in the canonical definition.

Its job is to say what the function is. It may be more explicit and less brand-like than the proper name.

**SOURCE FACT.** `Orienting Composition` currently has standing only as a qualified semantic proposal/descriptor from <issue id="18d74a2a-1a72-43e5-a068-5ab111860905" href="https://linear.app/ecos-ops/issue/ECO-153/naming-move-former-master-key-provisional-pgo-bounded-namecraft">ECO-153</issue>.

**SHAPE DECISION.** `Orienting Composition` remains a test subject for the descriptor role. It is neither frozen as the final descriptor nor permitted to seed candidate generation.

### Layer 3 — procedure / operation name

**SHAPE DECISION — SEPARATE.** Any procedure that derives, resolves, recomputes, updates, inspects, or otherwise operates on the focal function receives its own operation/procedure designation only if a distinct procedure is actually warranted.

Historical Decoder Ring provenance makes this separation mandatory at the conceptual level even if a future implementation exposes a very compact interface.

The proper name must survive sentences that distinguish “the function” from “running a procedure concerning the function.”

### Layer 4 — materialization / representation name

**SHAPE DECISION — SEPARATE.** A stored, transmitted, rendered, or otherwise materialized representation is not the function.

Orientation Resolution remains a neighboring materialization/representation concept and is not renamed or absorbed by this naming Move. A function may have multiple materializations, no current materialization, or a materialization whose authority/currentness has changed.

The proper name must remain valid in all of those states.

### Layer 5 — machine identifier

**SHAPE DECISION — DEFERRED UNTIL WARRANTED.** Schema, API, registry, tool, or code identifiers do not drive the human/system name.

A machine identifier is derived only after the naming result and the relevant implementation surface are known. It must pass its own normalization/collision constraints. Selection of a human proper name does not automatically authorize a schema/API rename.

### Cross-layer alias and supersession behavior

Alias/supersession handling is an interface obligation rather than a sixth named referent layer.

Historical and provisional aliases must remain traceable after a later adoption, with explicit standing. A later canonical adoption must not rewrite historical artifacts as though they had always used the new name.

**SHAPE RESULT.** The <issue id="e777f03c-a616-47f3-974f-d8b5c247217c" href="https://linear.app/ecos-ops/issue/ECO-157/sense-first-class-name-provenance-naming-architecture-former-master">ECO-157</issue> hypothesis is accepted: **first-class proper name + recoverable semantic descriptor** is the governing interface architecture. One string may lawfully serve more than one layer only if it passes the relevant distinctions without collapse.

## 3. Hard rejection gates

These are conjunctive safety gates. A material failure is disqualifying. Memorability, beauty, resonance, brand fit, or human preference cannot compensate.

A candidate is rejected if it materially does any of the following:

| Gate | Failure condition |
| -- | -- |
| Wrong referent | Names only a constituent such as goal, frame, scope, context, stopping condition, resolution, or packet rather than the focal function. |
| Object reification | Encourages the function to be understood as one key, packet, document, token, file, container, or other single material object. |
| Procedure collapse | Names the process that derives/updates/inspects the function rather than the function itself, or makes the two operationally indistinguishable. |
| Neighbor collapse | Collapses into Orientation Resolution, Orientation Scope, Qualification, Current Binding / Binding Transition, Authority Decision, Move, or Question Forward. |
| Authority inflation | Implies the function creates, owns, or is the Principal/authority source. |
| Action inflation | Implies possession or resolution of the function itself authorizes external action. |
| Closure inflation | Implies exhaustive, universal, permanent, or global closure rather than bounded semantic closure for the present interpretation/action envelope. |
| Currentness collapse | Fails when no materialization is current, or implies that newest/represented/resolved necessarily means currently bound. |
| Materialization collapse | Cannot coherently describe multiple materializations of one function or one materialization becoming stale without the function ceasing to exist. |
| Unresolved-authority failure | Ceases to make sense when authority is unresolved or authority sources change. |
| Inherited-meaning redirection | Imports technical, legal, scientific, cultural, or metaphorical entailments that materially redirect the referent. |
| Repair dependence | Requires a strained expansion, disclaimer, or descriptor to undo a misleading core name. |
| Retrieval failure | Is too generic, collision-prone, or semantically noisy to function as a reliable address in required internal retrieval surfaces, absent a bounded repair that itself preserves the name’s integrity. |
| Identity failure | Cannot meet the minimum first-class identity floor for routine invocation and durable discrimination. |

A superficial imaginative misreading is not enough to fail a candidate. The wrong inference must be plausible and consequential under an intended use surface.

## 4. First-class identity floor

Semantic adequacy is necessary but not sufficient. A surviving candidate must also function as an identity.

### Invocation and pronunciation

**SHAPE DECISION.** The name must be effortless enough for repeated spoken use. It may require one pronunciation instruction if the pronunciation then remains stable and easy to recover. Chronic hesitation, competing pronunciations that alter identity, or routine substitution by users is a failure signal.

### Memorability and recognition

**SHAPE DECISION.** A human operator should be able to recognize or recover the name after low exposure and intervening work. This is partly behavioral and cannot be certified analytically in Shape.

A candidate may therefore be **analytically qualified but human-recognition unverified**; it may not be called fully qualified-in-use until observed.

### Corpus discrimination

**SHAPE DECISION.** The name must be discriminable by exact/string search and by the semantic-retrieval surfaces that will actually carry continuity. A name that can only be found when the full descriptor is supplied does not yet function as an effortless address.

### Compositional prose behavior

The name must sit naturally in:

* a request;
* a technical explanation;
* a disagreement;
* a status report;
* a provenance note;
* a reference to a current or historical representation.

Normal usage should not require continual grammatical repair or an unofficial substitute name.

### Durability under architectural growth

The name should bind to the stable structural center of the function rather than an incidental current implementation, storage shape, historical metaphor, or temporary workflow.

Architecture growth may enrich the descriptor without forcing identity churn.

### Sibling coherence without mimicry

The name should be recognizably native beside SIGMA, ECOS, BRAIN, Crucible, and other first-class ECOS vocabulary while not imitating the visible form of any one sibling merely to look related.

Acronymicity, capitalization pattern, metaphor style, word length, or mythic/scientific tone are not family requirements.

### Progressive disclosure

The token should support this sequence without contradiction:

`name → descriptor → full definition → provenance`

A cold reader may initially treat the name as an opaque address, but deeper disclosure must strengthen rather than reverse the initial interpretation.

### Written/spoken identity stability

Likely capitalization, possessive, plural, abbreviation, and spoken forms must not create a second competing referent or encourage process/artifact confusion.

## 5. Multiplicative-value dimensions

These dimensions are considered **only after** a candidate passes the hard rejection gates and first-class identity floor. They are surplus value, not repair mechanisms.

The later Move should inspect the following separately rather than collapsing them into a weighted score:

| Dimension | Multiplicative value when earned |
| -- | -- |
| Disciplinary teaching | The name or honest expansion teaches real concepts from relevant disciplines through ordinary system use. |
| Layered honest meaning | Several independent readings all remain true of the same referent rather than producing clever but contradictory lore. |
| Symbolic / etymological resonance | Cultural, linguistic, mathematical, scientific, or etymological resonance deepens an already-correct name. |
| Form-function isomorphism | The form of the name mirrors an important structure or behavior of the referent without having been forced to do so. |
| Visual / typographic identity | The token affords distinctive, productive visual expression without introducing false semantics. |
| Morphological productivity | Natural compounds, possessives, short forms, or verb forms improve use while preserving category boundaries. |
| Cross-scale utility | The name remains useful across technical depth, ordinary conversation, diagrams, prompts, and documentation. |
| Retrieval synergy | Human memorability and machine discrimination reinforce each other rather than trade off. |
| Sibling-system synergy | The name creates useful family recognition or conceptual contrast with neighboring first-class names without mimicry. |
| Story / teaching leverage | The provenance or expansion provides a concise way to teach the function after the token has already earned identity standing. |

**SOURCE FACT.** The historical SIGMA protocol treats symbolic resonance and form-function isomorphism as discoveries rather than design goals.

**SHAPE DECISION.** The same doctrine governs here. A candidate does not earn survival by accumulating multipliers. Among already-qualified survivors, however, multiplicative synergy is a legitimate reason for human preference.

## 6. Eligible generation method families and lane-specific constraints

The later Generate phase must use multiple method families. The purpose is to protect the field from method monoculture.

### Lane A — forward-derived real-word acronym / disciplinary expansion

Function structure precedes letters. Expansion terms must be independently meaningful and load-bearing. No filler terms, no altered referent to make letters work, and no backronym repair.

Both the expansion without the token and the token without the expansion must remain defensible.

SIGMA and BRAIN are strong precedents, not mandatory molds.

### Lane B — layered acronym or brand expansion

A strong proper-name token may carry a brand-layer expansion, a disciplinary expansion, or more than one honest expansion if the layers do not disagree about the referent.

An expansion may enrich or teach. It may not be used to rescue a misleading token.

ECOS is the key precedent demonstrating that first-class identity need not depend on one constitutional acronym expansion.

### Lane C — established real-word appropriation / bounded metaphor

An existing word may be appropriated when its affordances help recognition and its inherited properties do not smuggle false structure into the system.

The lane must explicitly list the properties a competent reader is likely to inherit from the source word and then test literalization.

A bounded metaphor that must constantly be “unlearned” fails.

### Lane D — earned coinage / transformed word

Coinage, respelling, transformation, anagrammatic construction, affixation, or related word-shaping is eligible when the transformation earns functional or retrieval value rather than serving as decoration.

Pronunciation, spelling recovery, morphology, and explanation tax must be tested.

FIBERR is historical evidence that transformation can be earned after the function structure is stable. Its exact historical saturation gate is evidence about one route, not an obligation that all future transformed-word generation reproduce the same ceremony.

### Lane E — opaque proper noun

A semantically opaque token is permitted.

Because the name itself carries less descriptive load, this lane has stricter dependence on the recoverable descriptor, retrieval discrimination, pronunciation, and progressive disclosure.

Opacity is not a semantic failure; misdirection is.

### Lane F — scientific / symbolic / linguistic borrowing

A token may borrow from mathematics, science, linguistics, another language, or a symbolic system only when the borrowed semantics are inspected rather than used for prestige.

The lane must identify what practitioners of the source domain would reasonably assume and whether those inherited properties remain true or safely bounded.

### Lane G — direct functional / compound control lane

A direct functional or distinctive compound is retained as a control family so the process does not force novelty merely because the object is first-class.

This lane must still clear the first-class identity floor. An accurate phrase that behaves only as a generic heading is not automatically a first-class proper name.

### Lane parity rule

**SHAPE DECISION.** Every lane faces the same common hard gates, identity floor, test matrix, and selection architecture. Lane-specific constraints are additional obligations, never exemptions.

No lane receives a numerical quota advantage. A lane may return zero survivors. The acronym lane may not dominate because SIGMA succeeded there; the opaque/coinage/metaphor lanes may not win merely because novelty looks more “brandable.”

## 7. Generation independence and anti-anchoring rules

**SHAPE DECISION.** The later Generate phase is partitioned into independent lanes before cross-comparison.

Each lane receives the same frozen referent packet, boundaries, use surfaces, hard gates, and identity floor. It does **not** receive candidates from other lanes.

The incumbents and prior semantic proposal are withheld from generative seeding:

* Master Key;
* Principal Governing Orientation / PGO;
* generic Governing Orientation;
* Orienting Composition.

They remain required **control/test subjects** and are inserted only after an independent candidate field exists.

### Independence protocol

1. Generate independently within each eligible lane from the frozen referent and function structure.
2. Internally screen against that lane’s constraints and common hard gates.
3. Return only a small lane-local survivor set plus the lane’s strongest rejected pattern where the rejection teaches something materially distinct.
4. Do not force a lane to supply a survivor.
5. Only after all lanes close, reveal the cross-lane field, de-duplicate convergent candidates, and add incumbents/control designations for equivalent testing.
6. Do not improve a candidate by importing a rival lane’s logic until the first comparative test has recorded the original form.
7. If a lane produces no meaningful candidate because the method itself was under-instrumented rather than because the function resists that method, one bounded second pass is permitted. It is not a license to keep generating until every lane has a champion.

No fixed candidate count is imposed across the whole field. The stopping rule is information-based: generation stops when additional variants stop exposing a materially different naming trade-off.

## 8. Frozen candidate qualification and Overshoot matrix

Every candidate receives a disposition of **PASS / FAIL / CONDITIONAL / UNKNOWN / NOT APPLICABLE**, with basis identified as **source evidence / analytical inspection / observed use / hypothesis**.

A FAIL on a hard gate is terminal unless the candidate itself materially changes. A descriptor that merely explains away the failure is not a repair.

| Test surface | Required stress |
| -- | -- |
| Reduced-context expectation | Remove descriptor/explanation and ask what a competent user would think the token names. Then repeat with only the descriptor. |
| Semantic fit | Compare expected meaning with the exact focal function and its bounded closure role. |
| Structural fit | Infer participants, containment, transformation, state, and direction from the name; reject contradictions. |
| Constituent capture | Test whether the candidate really denotes only goal, context, scope, frame, stopping rule, currentness, or another component. |
| Function vs procedure | Put the name into “derive/update/inspect X” and “run X” constructions. Determine whether users can still distinguish function from operation. |
| Function vs materialization | Test “store/read/render X,” multiple representations, and one representation becoming stale. |
| Resolution distinction | Substitute Orientation Resolution into the same sentence and require the difference to remain recoverable. |
| Scope / Qualification distinction | Perform the same neighbor substitution for Orientation Scope and Qualification. |
| Current Binding distinction | Test a qualified-but-not-current representation and a no-current state. |
| Authority distinction | Change or leave unresolved the authority source without changing the function’s identity. |
| Action-authorization distinction | Ask whether resolving or possessing the function authorizes an external effect. The answer must remain no unless a separate authority layer says otherwise. |
| Multiple materializations | Two concurrent representations of one function must not imply two functions merely because there are two packets. |
| No-current state | The function remains nameable even when no representation is currently bound. |
| Recursive / map-assessment use | Make the focal function or its representation itself the subject of governed inquiry; the name must survive self-reference without ontological collapse. |
| Architecture / grammar change | Change a grammar or implementation version while preserving the focal semantic function. |
| Conversational use | Use the name in a request, explanation, disagreement, status report, and handoff. |
| Spoken use | Say likely forms aloud; test ambiguity with sibling names and likely ordinary-language homophones. |
| Abbreviation / plural / possessive | Exercise natural short forms and grammatical variants; distinguish one function from runs, packets, or records. |
| Verb morphology | If users naturally verb the name, test whether the verb refers to a legitimate operation rather than falsely turning the function into a procedure. No verb form is required. |
| Internal exact/string retrieval | Search the canonical repository and other required internal corpora for collisions and ambiguity. |
| Internal semantic retrieval | Search the actual semantic-retrieval corpus where continuity will depend on the name. Inspect the neighborhood, not merely presence. |
| External inherited meaning | Inspect common usage, technical terms of art, products/projects, and source-domain semantics. |
| Literalized metaphor | Treat metaphorical/symbolic content as literal and identify consequential false structure. |
| Sibling-system confusion | Place candidate beside SIGMA, ECOS, BRAIN, Crucible, Orientation Resolution, Move, Question Forward, and relevant nearby vocabulary. |
| False activation | Mention the token incidentally, discuss its name, or quote an old artifact. None should silently trigger a procedure or confer adoption/action authority. |
| Lifecycle / supersession | Encounter historical aliases, provisional use, a renamed version, and a supersession notice; identity and historical standing must remain recoverable. |
| Human memorability / enjoyment | After intervening work, test recognition, recall, willingness to use, substitution pressure, and whether any joke/resonance remains helpful. |
| Machine normalization | Only if a machine identifier is actually required: test casing, separators, namespace, collision, and action semantics independently of the human name. |

### Required usage specimens

The later Move should exercise, at minimum, sentences of these structural forms:

* “What is governing this inquiry?”
* “Resolve the \[proper-name referent / relevant operation\] before entering Shape.” The test must detect if the candidate falsely makes a function sound like the procedure that resolves it.
* “Under the current \[name\], this question is consequential.”
* “The \[name\] is compositional; this packet is only one materialization.”
* “The authority source changed, but this representation did not.”
* “This Orientation Resolution is qualified but is not currently bound.”
* “There is no current materialization, but the function remains defined.”
* “Two materializations disagree; neither fact alone creates a second governing function.”

The point is not that every sentence must accept the bare proper name grammatically. The point is to expose what category the name causes a reader to infer.

### Overshoot protocol

Promising candidates receive four deliberate break attempts:

**1. Context stripping.** Remove the expansion and descriptor; vary capitalization; use the likely short form; use spoken form; test partial recall.

**2. Competing interpreters.** Model an eager worker that thinks it already understands, an outside-domain expert carrying inherited meanings, and a human who remembers only part of the name.

**3. Literalize and multiply.** Treat metaphor literally; create multiple materializations, a no-current state, stale/current divergence, unresolved authority, changed authority, an obsolete representation, and recursive self-application.

**4. Corpus and lifecycle travel.** Place the candidate next to siblings and neighbors, retrieve it from the real corpus, mention it incidentally without invocation, and write a future supersession notice.

For every consequential failure, preserve the specimen, the wrong inference it permits, and the responsible repair layer:

* candidate itself;
* required descriptor/presentation;
* retrieval binding;
* procedure/materialization terminology;
* or, if the failure reveals a real conceptual ambiguity, return upstream to Sense.

External popularity alone is not disqualifying. The question is whether inherited meaning or collision produces material interpretation, retrieval, or public-use burden.

### Retrieval success criterion

No universal numeric rank threshold is frozen because the actual retrieval systems and result distributions differ.

**SHAPE DECISION.** A direct candidate query must make the intended referent recoverable without unreasonable interpretation/correction work on the declared surface. For semantic retrieval, inspect the returned neighborhood and whether the intended source is sufficiently discriminable to support continuity. Record scope and failure specimens rather than inventing precision.

The legacy SIGMA protocol’s embedding-neighborhood lesson is retained as evidence, but a single historical anecdote is not converted into a universal numerical cutoff.

## 10. Selection architecture and the role of human recognition

Selection is a **conjunctive cascade**, not a weighted score.

### Stage 0 — evidence completeness

Confirm that every material test has a disposition and that UNKNOWNs are visible. Unknown does not equal failure unless its alternatives could invalidate the selection.

### Stage 1 — hard semantic / structural gates

Reject every material failure. No multiplier enters yet.

### Stage 2 — first-class identity floor

Reject candidates that remain structurally correct but fail to function as durable, usable identities.

A candidate with untested human recall may remain CONDITIONAL rather than automatically fail if a bounded human-use trial can answer the question without hiding a known defect.

### Stage 3 — lane-specific integrity and Overshoot

Apply the additional obligations of the candidate’s generation lane and run the full Overshoot surface. Candidates that only survive in the protected context in which they were invented do not advance.

### Stage 4 — multiplicative-value comparison

Inspect surplus values as a vector, not a total score. Identify where one survivor strictly adds value without introducing a new liability. Do not convert subjective dimensions into fake cardinal precision.

### Stage 5 — direct survivor comparison

Compare the surviving independent field with the incumbent/control designations under exactly the same surface.

Switching cost and historical continuity may be recorded as lifecycle considerations, but incumbency itself receives no semantic bonus.

### Stage 6 — Principal / human recognition

**SOURCE FACT.** Scaffolded emergence says rigorous narrowing can create the conditions under which human taste/pattern recognition closes the final gap.

**SHAPE DECISION.** Principal recognition is a legitimate final selector **only among candidates that already survive the gates and identity floor**. Human preference cannot rehabilitate a semantic failure, authority inflation, retrieval failure, or other material defect.

Useful human evidence includes spoken preference, delayed recognition/recall, spontaneous substitution, willingness to use, and the felt “click” after the comparison field has been structurally qualified.

### Permitted selection outcomes

* one candidate analytically qualifies and the Principal recognizes it;
* multiple candidates qualify and Principal recognition or a reversible bounded use trial is needed;
* one or more candidates qualify analytically but human/retrieval evidence remains CONDITIONAL;
* **none qualifies**.

“None qualifies” is a first-class result. The next step then returns to the earliest responsible stage: Generate for field insufficiency, Shape for interface criteria problems, or Sense if a failure exposed an ambiguity in the referent.

No recommendation creates adoption authority. Canonical adoption remains a separate Principal disposition.

## 11. Required final naming interface

 1. **First-class proper name** — the exact proposed identity token.

 7. **Short form / abbreviation** — only if it independently passes category and retrieval tests.
 8. **Morphology** — plural, possessive, compounds, and verb form only where they preserve the distinction.
 9. **Referent / source binding** — durable pointer to the semantic contract and naming qualification record.
10. **Qualification status and evidence limits** — analytical, provisional use, or qualified-in-use; explicit UNKNOWNs.
11. **Historical alias / supersession treatment** — standing of Master Key, PGO, generic Governing Orientation, Orienting Composition, and any other aliases at the moment of adoption.
12. **Procedure relation** — separate operation/procedure terminology if such a procedure exists; never silently inferred from the proper name.
13. **Materialization relation** — explicit relationship to Orientation Resolution and any other representation.
14. **Retrieval binding** — where workers resolve the name and how failed retrieval is handled.
15. **Machine identifier** — only if independently warranted by an actual implementation surface after or alongside adoption.

A proposed proper name does not automatically authorize changing historical documents, database columns, API names, code symbols, or runtime behavior.
