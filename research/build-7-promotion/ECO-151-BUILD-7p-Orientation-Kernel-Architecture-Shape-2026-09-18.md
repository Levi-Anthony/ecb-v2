## 5. Selected physical architecture

Select a private schema provisionally named `ecb_orientation`. The name is physical/implementation-local and does not canonize public product vocabulary.

Core shape:

```
Versioned governing sources + URG manifest
                  |
                  v
         Orientation Resolution
      [immutable Text Artifact]
                  |
            Qualification
      [immutable Text Artifact]
                  |
          explicit authority
          resolution/decision
                  |
                  v
          Binding Transition
      [B11 operation + Artifact]
                  |
                  v
       Orientation Scope Head
      [epoch + current binding]
                  |
     +------------+------------+
     |                         |
 observation/change       public resolve
     |                         |
 applicability                  v
 assessment             B8′ / B9′ contract
     |
 material/unknown?
     |
  epoch fence
     |
 requalify / reaffirm
```

### Four separate state dimensions remain separate

1. **Representation** — Orientation Resolution Artifact.
2. **Qualification** — assessment of that exact Resolution for use/scope.
3. **Currentness** — current binding transition selected for an Orientation Scope.
4. **Authority/applicability** — independently resolved and recoverable status constraining whether the current binding may be relied upon.

No one record implies the others.

## 6. First-class subjects and source-of-truth boundaries

### 6.1 Orientation Scope — new Referent-backed subject

A stable scope/currentness slot.

Proposed typed state:

```
ecb_orientation.scopes
- id uuid PK -> referents
- focal_referent_id uuid -> referents
- scope_manifest_artifact_id uuid -> text_artifacts
- epoch bigint not null
- current_binding_id uuid nullable
```

The immutable scope manifest carries exact:

* focal identity;
* individuation/boundary;
* declared use class / governing envelope;
* scope identity basis.

A materially different boundary/use that changes what the scope *is* creates a new Orientation Scope rather than silently editing the old one.

Ordinary orientation changes within the same scope preserve the Scope identity.

### 6.2 Orientation Resolution — existing Text Artifact identity

No dedicated “resolution object table” is required merely to store prose/JSON semantics.

An Orientation Resolution is an immutable B12 Text Artifact containing an exact versioned manifest:

* focal Referent;
* scope ID;
* governing-source IDs/versions;
* grammar package/version;
* exact invoked capacity/obligation versions;
* declared use/telos/Move;
* evidence/access references and limits;
* authority references/status as known;
* material dependency manifest;
* QF/unresolved;
* stop/reentry;
* parent resolution where applicable.

The Artifact identity is the Resolution identity.

The Resolution is not current merely because it exists.

### 6.3 Orientation semantic record binding — new private typed binding

A small private immutable record binds:

* B11 operation ID;
* Resolution/Assessment/etc. Artifact ID;
* Orientation Scope;
* record role;
* observed/result epoch;
* validator/profile revision;
* optional reviewer capability.

This uses the <issue id="9007cfaf-1f89-4074-8a8e-13a82e8d8c53" href="https://linear.app/ecos-ops/issue/ECO-149/eco-136-register-b-implementation-quadrant-module-evidence-bearing">ECO-149</issue> pattern because the pattern produced discriminating evidence, not because quadrant records are authoritative for orientation.

### 6.4 Qualification — immutable Artifact + typed binding

The qualification’s semantic payload is an immutable Text Artifact.

Its private binding enforces:

* exact Resolution ID;
* exact scope/epoch observed;
* reviewer capability;
* method/remit/basis;
* result;
* use/applicability envelope.

### 6.5 Binding Transition — B11 operation identity + immutable transition Artifact

Each select/reaffirm/withdraw is a new operation identity and therefore already a Referent.

The transition also produces an immutable Text Artifact envelope carrying the full exact transition tuple.

The private binding-history row uses the operation ID as the transition/event identity and stores mechanically enforceable foreign keys/state fields.

### 6.6 Observation / Applicability Assessment

Observations are immutable Text Artifacts.

Where semantic judgment is needed, an applicability assessment is a separate authenticated immutable Artifact/binding.

A selected material/unknown applicability result can cause a mechanically fenced epoch transition.

### 6.7 Recovery/Requalification Projection

Derived read model by default.

Do **not** create a separate current projection table unless implementation demonstrates a decision-relevant query/recovery need not satisfied by the scope head + immutable history.

A materialized handoff Artifact may be created, but it is a representation, not the source of currentness.

## 8. Current-binding state machine

### Scope state

```
NO_CURRENT
  |
  | SELECT(resolution, qualification, authority decision)
  v
CURRENT(binding A, epoch N)
  |
  | SELECT new resolution
  v
CURRENT(binding B, epoch N+1)

CURRENT(A)
  |
  | material/unknown change fence
  v
CURRENT_BUT_REQUALIFICATION_REQUIRED(A, epoch N+1)

CURRENT_BUT_REQUALIFICATION_REQUIRED(A)
  |
  | REAFFIRM(A, new applicable qualification)
  v
CURRENT(new binding event A′, epoch N+2)

CURRENT(any)
  |
  | WITHDRAW
  v
NO_CURRENT(new epoch)
```

### Mechanical rules

Every currentness-changing transition:

* has stable B11 operation ID;
* has exact request digest;
* names scope;
* names expected epoch;
* names expected predecessor binding;
* names operation `select | reaffirm | withdraw`;
* atomically locks scope;
* validates the exact transition tuple;
* appends immutable history;
* advances epoch exactly once;
* updates `current_binding_id` atomically.

### ABA protection

A → B → A is represented by three distinct binding transition identities.

A request expecting the original A transition cannot succeed after B merely because the selected Resolution equals A again.

The expected predecessor is the **binding transition identity**, not merely the Resolution ID.

### Withdrawal

Withdrawal is an explicit immutable transition.

It advances epoch and sets `current_binding_id = NULL`.

Historical selected Resolutions remain intact.

## 10. Authority-resolution seam

There are two different authority questions and BUILD 7′ owns only the first seam:

1. **Orientation-binding/designation authority** — who/what may select or withdraw a governing Orientation Resolution for Scope S?
2. **External action/effect authority** — whether BUILD 8′ may execute a consequential action.

BUILD 7′ must never answer #2.

For #1, production authority source is not currently resolved. Shape therefore selects a **delegated Authority Decision interface**, not an invented authority provider.

A binding transition requires an exact Authority Decision reference whose resolver returns at minimum:

* authority subject/issuer identity;
* acting identity;
* scope;
* permitted transition operation;
* selected Resolution + Qualification tuple where applicable;
* predecessor/current binding;
* effective/revocation conditions;
* standing/currentness of that authority decision;
* exact evidence/provenance.

The Authority Decision may be represented durably by an Artifact/Referent, but its existence does not create authority. The resolver must establish standing from the actual governing authority source.

### Production activation rule

Until a real orientation-binding authority source/resolver is commissioned:

* BUILD 7′ may be implemented and qualified in isolated fixture mode;
* canonical production **selection/withdrawal activation is held**;
* read/recovery and non-authoritative formation may be separately considered later if warranted.

This unresolved authority source is an installation/activation dependency, not an Architecture Shape blocker.

## 11. Change / requalification flow

### Dependency manifest

Each Resolution Artifact carries exact consequential dependency entries:

* Referent ID;
* exact version/revision/digest or version locator;
* dependency role;
* materiality/use relevance;
* observation/access route if known;
* QF/reentry condition where unresolved.

Consequential edges may be mirrored as `depends_on` Claims for discoverability.

### Flow

1. **Observe** — record a new immutable observation/change candidate. No currentness effect.
2. **Assess applicability** — authenticated method decides one of:
   * unaffected;
   * materially changed;
   * unknown materiality;
   * incompatible / replacement required.
3. **Fence if needed**:
   * unaffected → preserve observation; no epoch/currentness change;
   * material or unknown consequential impact → guarded transition advances scope epoch while preserving current binding identity;
   * incompatible scope identity → route to new Scope / refocus rather than mutating current Scope.
4. **Resolve present state** — if current binding was qualified at an older relevant epoch, return `requalification_required`; do not manufacture positive reliance.
5. **Requalify** — assess exact Resolution against current basis.
6. **Reaffirm or replace**:
   * same Resolution still applicable → new `reaffirm` binding transition with new qualification;
   * changed Resolution needed → `select` new Resolution;
   * no acceptable basis → remain current-but-unreliable / withdraw according to authority decision.

### Grammar version changes

New grammar bytes/version alone do not globally invalidate old Resolutions.

Assessment asks whether the semantic change is material to the Resolution’s declared use/scope.

Same meaning / compatible representation may remain applicable.

Changed discriminator/obligation affecting the declared use routes requalification.

Unknown materiality fences dependent positive reliance but does not erase history or globally invalidate unrelated scopes.

No universal monitor is selected. Change enters through actual evidence return, use-time checks, declared sensors/routes, or explicit review.

## 14. Adversarial walkthrough

### Same operation replay / changed request

B11 exact operation identity returns committed result for same digest and rejects changed tuple.

### Concurrent binding transitions

Scope row lock + expected epoch + expected predecessor yields exactly one currentness transition.

### A→B→A ABA

Binding event identity, not Resolution identity, is the predecessor token. Old A predecessor cannot be replayed as current after B.

### Qualification for wrong Resolution/version

Private qualification binding requires exact Resolution Artifact identity and immutable payload/reference closure. Mismatch rejects.

### Valid Resolution, unresolved authority

Resolution/qualification may exist. Binding transition cannot produce a positive current binding unless an applicable Authority Decision is resolved.

### Authority revoked after binding

Historical binding remains. Resolver returns authority revoked/unresolved for fresh reliance; currentness history is not erased. Separately authorized withdrawal/replacement may follow.

### Grammar same-meaning version change

Observation recorded. Applicability assessment may leave epoch unchanged if decision-equivalent for declared use.

### Grammar semantic change affecting one use

Only affected scope/use is fenced/requalified. No global invalidation.

### Missing historical payload

Requalification cannot substitute a digest/latest representation for missing old meaning. Resolver returns bounded loss/unknown.

### Raw Artifact says PASS/current

No effect. Typed binding/qualification/currentness records are required.

### Newest Resolution is not current

New Artifact remains a candidate until explicit binding transition.

### Changed downstream use

Public resolver’s declared-use envelope does not transfer qualification to a materially different consumer use; consumer must reenter.

### No-route material QF

Dependent positive reliance reports suspended/unknown; unrelated custody and unaffected use may continue.

### Reviewer unavailable/revoked

No fresh positive qualification. Prior evidence remains historical.

### Restart/cold recovery

Scope head + immutable transition/Artifact closure reconstructs state without conversation memory.

### Withdraw/no current

Explicit withdraw transition advances epoch and sets head to no-current; latest Resolution remains merely historical/candidate.
