SELECT ecos-translation-frontier — The task names one exact sufficiency claim and asks for an indexed-category countermodel, which is a selected formal-correspondence test rather than open-ended exploration.

## Raw answer

**Claim tested.** “Old load evidence determines all destination permission obligations.” For a falsifiable reading, “determines” means that any two destination accounts with the same old, source-visible load records have the same coverage of a permission obligation required for the destination use. This is my explicit reading of the task, not a recovered ECOS definition. If “determines” instead means discovering which permissions are required, the destination use and its rules also have to be supplied; old load records alone contain no such rule. No source packet establishes actual ECOS obligations, a valid grant, or a qualified semantic bridge here.

**Operational commitment.** In a stipulated fixture, the old interface asks for a load receipt `L`; the destination deployment asks for `L` and a separate permission grant `P`. An old-only checker sees `L` in both accounts below. If it declares destination permission covered on that basis, it accepts an account without `P`. Nothing in this fixture says a real deployment uses these rules or that an arbitrary permission record would be valid.

**ORIENT.** An indexed category organizes a category of record accounts for each slot interface, with restriction maps for comparing interfaces. Its ordinary mathematical job here is to preserve what a smaller interface can see and obey identity/composition laws. It is useful because the claim is a determination claim: does forgetting destination-only slots lose a decision-relevant distinction? Restriction is neither an ECOS authorization nor a proof that a slot correspondence is semantically qualified.

**FORMAL / SYMBOLS.** Let the source slot set be `I={load}`, the destination slot set be `J={load, permission}`, and `i:I→J` include the load slot. In the toy record universe `U={L,P}`, let `C_K=(𝒫(U))^K`: an object `X` assigns a set of records `X(k)` to each slot `k` of interface `K`; arrows are pointwise inclusions. Restriction `i*:C_J→C_I` is defined by `(i*Y)(k)=Y(i(k))`. This is an instance of the contravariant indexed category on slot sets: for composable maps, `(g∘f)*=f*∘g*`, and `id*=id`. These equalities hold by direct substitution, regardless of whether any application-specific comparison is qualified.

**NAME / TOKEN and pronunciation.** `C_K` is “C sub K”; `𝒫(U)` is “the power set of U”; `i*` is “i star”; `→` in the displayed types is “to”; `∘` is “composed with,” with the right operation applied first; `∅` is “the empty set”; `≠` is “is not equal to.” Subscripts zero and one below label two possible accounts, not successive times. The star's direction is determined by the stated definition, not by its typography.

**SAY FORMALLY.** “i maps I to J. i star maps C sub J to C sub I. i star of Y at k equals Y at i of k. For maps f and g in sequence, g composed with f star equals f star composed with g star, under the displayed parenthesization.” The last sentence means `((g∘f)*X)(k)=(f*(g*X))(k)` when `f:I→J`, `g:J→K`, and `X∈C_K`.

**SAY NATURALLY / READ.** Restriction asks which records a destination account presents on the old load slot. Its compositional law ensures that two steps of forgetting give the same old view as one combined step. That law does not restore records in a slot the old interface did not contain.

**WORKED EXAMPLE and countermodel.** Define two destination accounts:

| Account | Load slot | Permission slot | Toy permission coverage |
|---|---|---|---|
| `Y₀` | `{L}` | `∅` | No |
| `Y₁` | `{L}` | `{P}` | Yes, assuming `P` qualifies under the stipulated toy rule |

Both restrict to the identical source account: `i*Y₀=i*Y₁`, with load slot `{L}`. Yet `Y₀(permission)≠Y₁(permission)`. Let `R(Y)` mean that the destination permission is covered by a qualifying `P`. Then `R(Y₀)=false` and `R(Y₁)=true`. There can be no function `h` of the source-visible account alone for which `R=h∘i*` on these two accounts: `h` would receive the same input and have to return two different answers. This two-object countermodel refutes determination by old load evidence in the declared model. An old graph may keep its load support intact while the destination permission check remains open.

**System application and break boundary.** Exact restriction of attributed records is legitimate indexed machinery. The rejected extension is “therefore the old load view supplies or decides every destination permission.” Permission coverage requires destination disclosure and an independently qualified authorization check. If the question is the *set* of obligations rather than coverage, compare a test use requiring only load with a deployment use requiring load plus permission: the identical old `L` cannot decide which destination rule applies without the destination use/rules. A special governing axiom could supply a complete bridge, but it must be stated and tested; it is absent from this task.

**Bounded standing.** REJECTED MAPPING for old-load-only determination of destination permission coverage under this fixture. DIRECT FORMALIZATION applies to the toy restriction and its non-injectivity, not to ECOS deployment or whole-event qualification. The repository draft `ecos-translation-frontier` v0.1 at main `8165306eeb5fe2c624cb2f8d05e2ac5632abac91` guides this test but supplies no governing source packet for the particular real-world use. The next discriminator is a versioned destination requirement rule and any claimed complete, qualified bridge from load evidence to permission; test whether two accounts can still agree on the old view and differ on a required permission. Until then the actual ECOS standing and validity of any grant remain unknown.
