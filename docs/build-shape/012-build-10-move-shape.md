## 7. Custody and transfer topology

`S Artifact body -- sender memory / parameterized PG bytea call --> D retained body`

`S exact independent basis -- trusted resolver, read-only snapshot --> D per-check basis observation --> D SQL checker`

S: `ecb10-source-pg17`, database `build10_source`, loopback port 55443. D: `ecb10-destination-pg17`, database `build10_destination`, loopback port 55444. Image `pgvector/pgvector:0.8.2-pg17`, record actual image ID. Separate named volumes, no shared data-directory mount. Host/DDL/release custodian is trusted; independence from a hostile host is not claimed. Setup refuses nonallowlisted destinations and existing resources without exact labels/identity verification.

The sender alone can read exported P body from S and invoke D receipt functions. It cannot read independent criterion/evidence through source privileges or write assessments. The resolver is a separate executable invocation with source-read-only basis access and D resolver-only access. Ordinary D clients and the cold CLI possess no S credential. No network service, FDW, dblink, arbitrary URL or destination discovery is required: the admitted controller invokes this bounded resolver process with the committed check UUID; resolver looks up the immutable D check/question before resolving exact S IDs. The executable is a declared trusted read interface, not producer-supplied code.

The selected representation is a transport identity frame plus a raw content body. Frame carries source namespace, source Artifact UUID, projection UUID/version and body byte count. Body carries focal/revision, report/version, projection contract/version, finite proposition and dependency manifest. D retains both frame and body. Producer frame claims are compared to independently pinned source export. Equal raw bodies under distinct source Artifact identities remain different representations; byte equality never deduplicates their identity frames.

No serialization of a parsed source object substitutes for selected bytes. S export binding digests the actual stored body. Sender passes those octets unchanged except when the fault harness deliberately corrupts/truncates them. D complete receipt stores actual octets even if invalid. Integrity and semantic qualification occur later.

## 10. Actual content, integrity and finite language

D pins `b10-comparison-json/v1`, strict UTF-8, SHA-256, maximum body 64 KiB, unique JSON keys at every level, exact admitted object fields and finite arrays. Receipt may retain invalid encoding/JSON; checker handles decode/parse exceptions as findings, never loses the receipt. Canonical base64 is checked by decode/re-encode after stripping encoder line breaks. Partial is at most one nonempty strict prefix, not a resumable chunk protocol.

Body fields are `language`, `focal`, `revision`, `report`, `report_version`, `projection`, `projection_version`, `contract`, `contract_version`, `manifest`, `proposition`, `expressions`, `limits`, `encoding`, `integrity`. Identity values are UUIDs plus exact version strings; encoding/integrity strings must equal D's pinned values.

`proposition` contains `quantifier` (`all` or `average`), `population` (exact observation UUID list), `operator` (`le`), integer `threshold`, `unit` (`ms`), `context` (warm-start/single-request), `asserted_result` (boolean). Finite integers are 0..1000000; compute using PostgreSQL numeric, no floating-point tolerance. Independent criterion must express all/le/100/ms, and evidence context must match. All means every selected value <= threshold. Average is interpretable but is a Q1 preservation violation even when numerically true. Population compares as a unique set plus exact selectors; order carries no meaning. Limits must contain exactly the admitted historical/synthetic and excluded-use vocabulary, with no widening.

Every `expressions` item is either the exact textual rendering `each declared observation met the threshold`, `not every declared observation met the threshold`, or `execution permitted`, or a typed expression with the same finite proposition fields. Each is interpreted independently and checked for agreement with the main proposition, independent consequence and local-use rule. `execution permitted` is understood but forbidden: REJECTED. No free-form summary is ignored. Unknown expression text, operator, language or extra decision-bearing field yields INDETERMINATE; absent mandatory syntax/type or invalid bytes yields REJECTED. Correct typed fields with contradictory summary are REJECTED. An absent expressions list is malformed, not an empty proof.

Checker component findings: raw integrity/encoding; provenance; exact identity/participation; manifest completeness; meaning/scope preservation; evidence consequence; all-expression consistency; permitted historical use; method availability/binding. Findings retain actual observed value, required comparator and relevant input IDs. No fixture UUID switches or producer PASS branches exist.

Outcome precedence: any established integrity/provenance/identity/semantic violation -> REJECTED_FOR_Q1; otherwise any unsupported interpretation -> INDETERMINATE; otherwise indispensable unavailable receipt/basis/check capability -> INCOMPLETE; otherwise all required checks true -> SUPPORTED_FOR_Q1. Not-run components explicitly retain their blocking dependency. An interrupted transaction yields no terminal, not INCOMPLETE by inference. The resolver's availability status alone never yields support.

Semantic negative exports are minted under trusted release custody with their own valid export digest. For P02/P03, prerequisite assertions must show complete receipt, good digest/provenance and correct non-varied bindings before interpreting semantic rejection as proof. At least one post-freeze semantic holdout must vary an admitted expression or context combination not used to tune the checker; record freeze and holdout provenance, and do not claim specification independence from the same worker.

## 11. Destination checker and independent source basis

Source release custodian installs report, criterion, W1/W2, population selector/unit/context and export bindings independently from producer body/descriptive metadata. Export registration proves selected bytes came from the declared synthetic source; it deliberately accepts semantically bad bodies for negative controls. Producer cannot edit that basis or nominate another resolver.

The trusted resolver receives only check UUID. With D resolver role it reads the committed check and Q; with S basis-reader role it executes one read-only repeatable-read transaction selecting the exact named records/export. It returns records/missing observations, never a verdict or replacement P body. The immutable observation is written to that exact D check through a resolver-only function. A network failure is an unavailable observation; a crash before recording remains unresolved until a new resolver invocation records or recovers the existing observation. Only one observation per check; changed observation conflicts, requiring a new check for fresh source state.

`ecb10.finish_check(check_uuid)` accepts no payload, verdict, checker name or arbitrary basis. It reads actual D copy, immutable Q, pinned method, integrity observation and resolver observation and computes findings in SQL. The method Artifact records version and digest of exact installed checker/parser/helper definitions in a fixed sorted function inventory. Finish recomputes that inventory digest; mismatch or unavailable method refuses qualified execution. A small protected unavailable-method path publishes INCOMPLETE with missing-method finding and no semantic verdict; it cannot publish support. Installed wrapper/privilege/DDL definitions are included in release freeze evidence, not claimed immune to hostile owner modification.

Pristine S representation stays available during defective-transfer tests. Checker cannot read it: resolver output excludes representation body, and D SQL has neither S credentials nor cross-store query facilities.

## 13. Transactions, partial receipt, replay, acknowledgement, competition

Selected APIs (all UUID arguments exact; structured values validated):

1. `admit(question,request,frame,previous_attempt)` commits a delivery independently. Replay same request/full tuple returns its existing delivery; changed tuple is conflict. Previous attempt must be an existing D delivery for same source/question; it is lineage only.
2. `observe_partial(delivery,bytes)` commits one strict prefix observation; exact replay recovers it; different prefix conflicts. It never creates a complete copy. Empty/no-data remains admitted-without-receipt.
3. `complete(delivery,frame,bytes)` commits one copy and DB-derived raw count/digest atomically. It compares frame to admitted frame and, if present, verifies partial prefix correspondence. Declared full count must match actual count for completion; wrong content of correct size is retained and later rejected by integrity. Truncated completion stays a partial/error observation, never complete. No source lookup qualifies completion.
4. `begin_check(delivery,request,method)` commits an independently identified attempt binding the exact complete copy if present. No copy binds null permanently. Installed/Q method mismatch is observed; no attacker-selected checker executes.
5. `observe_integrity(check)` separately commits DB-derived raw digest/count/encoding observations from the bound copy and pinned D rules. Replay recovers the exact observation.
6. Trusted `resolve(check)` commits one fresh independent source observation, or unavailability. It may follow integrity failure so that P02/P03 controls can demonstrate independently valid provenance; no semantic result comes from it.
7. `finish_check(check)` publishes findings and terminal as one Artifact in one local transaction. Before required observations exist it returns unresolved rather than fabricating missing-source facts. Null-copy or explicitly unavailable-method paths may publish bounded INCOMPLETE after their required observations. Repeated finish returns exactly the same assessment ID/content.
8. `report_sender(delivery,observation_uuid,reported_status)` appends untrusted sender-observation testimony, restricted to known status vocabulary; never receipt evidence. Sender also persists selection/attempt/ack-or-unknown observations at S using the same observation role and source context. These are distinct from D facts.

Each phase function requires READ COMMITTED and uses a transaction-local advisory lock on a fixed hash of its delivery/check UUID before checking/inserting. Hash collisions merely over-serialize. Unique indexes provide final race protection. No lock spans stores or calls. Calls reject completion/check progression from an attempt created in the same top-level local transaction, using local created_xid solely as a prior-commit discriminator (never exported order). Check admission also requires the bound complete copy to preexist that transaction. Observation and finish similarly require a previously committed check. No cross-store atomicity is invented.

Admission, prefix, completed copy, integrity, check and terminal are distinct persisted subjects. D restart/connection death after each commit exposes that exact prefix of facts. Failure inside terminal publication rolls back the whole terminal; preexisting check remains unresolved. A transaction that never committed creates no claimed durable fact.

Exact wire replay uses the same delivery UUID/request and bytes; it recovers existing receipt. A deliberate new delivery uses a new request/attempt UUID and optional previous-attempt ID, preserving history. Same bytes with another S representation ID requires distinct delivery binding. New Q/report/criterion/evidence/method requires new immutable contract/binding and check; old results remain historical.

For lost acknowledgement, sender records UNKNOWN unless it actually observed the response. It queries exact D delivery/copy/check IDs via read-only observation. If available, it learns D's committed facts; this does not retroactively mean the original ack arrived. If query unavailable, UNKNOWN remains. Bounded manual retry may replay the exact request; no autonomous retry, eventual completion or semantic exactly-once assertion.

Concurrent complete calls for one delivery produce one copy or a differing-content conflict. Concurrent finish calls for one check produce one assessment; different check attempts may each publish a terminal. No consensus or unique semantic answer across attempts is claimed.
