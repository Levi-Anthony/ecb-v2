## Governing distinctions

Salience means currently attracting attention. Significance concerns structural consequence under the stated referent/basis. Importance concerns value under the governing orientation. Decision relevance concerns whether the information can change the current warranted action, acceptance or dependency. They are separately attributed judgments; there is no universal numeric ranking or multiplication formula.

The Pareto/Zeno diagnosis is the Principal's: locally true arguments can isolate a work surface from its containing outcome and its realization dependencies. The intervention is a closed control cycle. Exploration remains available. A proposed expansion must name the current obligation it changes, the failure caused by omitting it, its evidence, its bounded completion criterion and its return route. Existing required work continues while the proposal is decided. Proposals cannot become work by repetition, confidence or salience.

## The production cycle

Plan → implement → verify → deploy → validate → metabolize → close. Planning carries the complete acceptance contract, not just a list of coding tasks. Verification checks the specified result against its contract. Validation checks whether the deployed result actually fulfills its situated purpose. Metabolization checks incorporation into the containing system, including changed old support and new obligations. The stage names are operational coordinates, not replacements for Sense / Shape / Move / Metabolize governance.

A required obligation is paid only by a current PASS from its named validator, for the exact cycle edition, with recovered native evidence whose content digest matches. The validator's attribution does not independently establish semantic truth. An obligation needing independent validation records that requirement and rejects the executor as validator. Child work must close and return; its local status is insufficient.

Zero balance is a predicate over all required work and fallout in this commissioned outcome, including descendants. An unrelated future opportunity may be routed with an owner, trigger and a reason it does not affect present acceptance. It does not become a completed obligation. A genuinely necessary discovery is admitted into this cycle and increases visible debt. Required work cannot be erased by routing it away.

Changing the relied-on edition reopens the affected cycle at planning and invalidates its previous result reliance. An evidence correction can reopen a closed cycle; containing cycles must also requalify. Events retain the historical result rather than rewriting it as if it never happened.

Two ordinary Model Context Protocol tools expose inspection and commands using existing recovery/transition capabilities; the authenticated HTTP route exposes the same records for human/client access. Technical capability does not commission a new actor. Only actors explicitly registered under a current workflow commission may mutate its cycles.

`workflow_inspect` returns current debt, child dependencies, unresolved scope decisions, next work and event history. `workflow_command` supplies a stable operation identifier and expected cycle version. Retry the same operation after a lost acknowledgement; change neither its payload nor actor. Reinspect after a version conflict.

Coverage: workflow state transitions and result reliance through this native controller are structurally enforced. GitHub/Linear writes made outside it are separate paths. The recurring reconciliation checks their observed status against workflow liabilities and routes discrepancies; it cannot authorize production/provider effects or certify missing semantic evidence. Frozen consumer tool snapshots require their existing owner to refresh before the new tools are claimed exposed.
