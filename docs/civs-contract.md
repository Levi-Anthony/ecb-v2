# Capability Inspection Record contract — WP1/WP2

**Contract:** `ecos:capability-inspection-record:0.1.0`  
**Relation schema:** `ecos:civs-object-relations:0.1.0`  
**Scope:** reusable CIVS inspection record + typed object connections. This does not add a URG primitive or correspondence formalism.

## WP1 — record contract

A Capability Inspection Record (CIR) is an inspection projection over independently standing objects. It does not become the authority for GitHub, BRAIN, Linear, deployment state, native-domain meaning, or consumer behavior.

The eight installation names are **independent assessments**, not an ordinal lifecycle state. A deployed capability can remain unexposed; an exposed capability can remain unqualified in situated use; operational sustainment requires its own evidence.

Physical realization is likewise a set of independently located coordinates—repository, runtime module/process, deployment, ingress, persistence and consumer surface—not a presumed linear pipeline.

The executable contract uses the governing enforcement modes STRUCTURAL / SEMANTIC / AUTHORITY / OBSERVATIONAL. Human/agent participation and mechanization are not used as synonyms for those modes.

## WP2 — typed object connections

CIVS reuses URG `native_relation` only through the scoped schema `ecos:civs-object-relations:0.1.0`. Each relation kind has explicit role-bearing participants and semantics. Persistence of a relation record does not establish relation truth.

The scoped kinds are: specifies, implements, tests, qualifies, deploys, exposes, coordinates, depends_on, evidence_for, question_forward_for, projects_to and supersedes.

This is deliberately **not** a generic edge bag. A `source -> target` pair with no declared relation kind/roles/basis/standing is invalid.

## Anti-reification constraints encoded by the validator

- no scalar `installation_status`;
- no generic top-level `owner` where roles differ;
- working vertical band does not establish URG Level;
- Consumer Simulation carries its own R/B/G/F/use basis;
- LATENT/LOCATED are local consumer-correlation binding statuses only;
- affordance/accommodation/continuity/accountability remain local support claims;
- graphical-door readiness is seven independent obligations, not a boolean;
- field reconstitution remains a pattern over typed Change + dependency/requalification, not a new Change kind;
- verification links name bounded propositions, sensitivity evidence and limits rather than implying transitive proof;
- correspondence inspections preserve semantic owner, evidence/currentness and unresolved mathematical requirements without selecting a formalism.

## Two-door behavior

`renderCapabilityInspectionRecord()` generates the human-readable view from the same machine CIR. `makeCivHumanProjectionRecord()` can bind that view through an installed URG `ProjectionRecord`. The view is therefore a projection of the same inspected record, not a second truth store.
