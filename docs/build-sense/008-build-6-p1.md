## Current uncertainty — UNKNOWN / DEPENDENCY

The first material unknown is normative, not technical: whether the already-qualified explanation-toggle specimen is intended to become the first real P1. No existing source upgrades that test specimen into Levi's decision.

A second implementation dependency remains even if that candidate is selected. M2's private helper is bound to the exact genesis request and installer flow; it is not a general P1 runner. ## Apparent tensions to resolve, not paper over

The release package expects ordinary succession to prove both human decision issuance and bounded execution. Human authority must remain inside the protected WebAuthn/session route, while executor custody must remain outside the human service and ordinary agent's human-session capabilities. We therefore need a route that makes execution easy enough to perform without collapsing these boundaries.

The test specimen is maximally small semantically, but smallness does not make it the desired real policy. Conversely, inventing a more meaningful P1 merely to avoid a test-looking change would add semantic scope and reduce diagnostic clarity. The first real successor should be selected for both actual acceptability and evidentiary value.

The existing browser can review arbitrary exact bytes, so a new UI is not required for correctness. Manual copy/paste of 563 exact bytes is possible but introduces unnecessary formatting/digest risk. Whether to add a tiny candidate-loading convenience or use a repo-fixed file/manual paste belongs in Shape only after the exact candidate is selected.
