# ECB v2 Build Contract

## Master Key

**Governing ideal**

Produce the smallest clean ECB v2 substrate capable of preserving OB1’s disproportionate value while carrying forward only ECB extensions whose value and architectural necessity have been demonstrated.

**Relevant distinction**

proven capability ≠ inherited implementation

**Current leverage**

Separate harvesting from rebuilding.

**Revalidation trigger**

Reopen the build boundary only when a real vertical slice cannot be implemented without violating an invariant or repeatedly reconstructing a distinction that has clearly earned persistence.

## Lineage

ECB v2 is not a rewrite of ECB v1.

- OB1 is substrate lineage.
- ECB v1 is evidence.
- ECB v2 is greenfield.

Preserve behavior before implementation.

Do not migrate complexity merely because it already exists.

## Layer A — Open Brain evidence substrate

Layer A must remain useful independently of governance.

Minimum capability:

- thoughts;
- embeddings;
- semantic retrieval;
- stable timestamps/identity;
- source/provenance metadata;
- MCP capture;
- MCP retrieval.

Thoughts are atomic evidence records.

Semantic retrieval remains the fallback path when richer structure has not earned persistence.

## Layer B — Governance primitives

Begin with five logical primitives:

**Referent**  
Universal stable identity for persistently addressable governance objects.

**Claim**  
Assertion or typed relation with scope, provenance, and standing.

A referent-to-referent relation is expressed as a claim. Do not create a competing relation truth store merely for convenience.

**Evidence Link**  
Stable typed connection between a claim/evaluation and versioned evidence.

**Event**  
Immutable transition/history record.

**Artifact**  
Immutable or versioned representation such as a map, receipt, Master-Key expression, semantic evaluation, envelope, policy, or packet.

Specialized physical structures are promoted only when earned.

## Structure is earned

Dedicated persistence may be introduced when generic representation creates:

- integrity problems;
- recurring semantic ambiguity;
- repeated difficult queries;
- transactional requirements;
- measurable performance problems;
- repeated reconstruction risk.

Philosophical importance alone is insufficient.

## Promotion vocabulary

Keep distinct:

**Referent registration**  
Stable addressability.

**Semantic promotion**  
Change in structured claim/governance standing.

**Schema promotion**  
Movement from generic representation into dedicated physical structure.

None implies another automatically.

## Governance activation

Currentness is explicit.

Newest does not mean governing.

Before any consequential governance-dependent action is enabled, v2 must implement:

bootstrap trust root → initial policy activation → human/warrant authority designation → bootstrap exhaustion → ordinary governed succession

Governance state must be reconstructible after restart.

## Runtime boundary

Tiny SSMM is not reopened here.

When governance becomes active, runtime receives a validated, designated action envelope.

Governance retains the conditions that made the envelope legitimate.

## Recursion

Self-hosting means governance objects can themselves become focal referents using the same grammar.

Recursive inspection is lazy.

Open recursive inspection only when an encountered condition creates material uncertainty about legitimacy, orientation, standing, warrant, scope, propagation, consequence, or permitted action.

Do not instantiate conceivable recursive depths merely because they exist conceptually.

## Definition of forward motion

Forward motion occurs when another valuable or architecturally required behavior becomes reproducibly possible on the clean v2 substrate while preserving the invariants.

Forward motion is not measured by:

- concepts defined;
- schema count;
- v1 code ported;
- automation count;
- tool count.
