# Constitutive Invariants

Implementation SHALL preserve recoverability of these distinctions:

- referent ≠ map
- map ≠ mapper
- evidence ≠ assertion
- identity ≠ description
- thought ≠ promoted object
- unknown ≠ nonexistent
- unclassified ≠ invalid
- omission ≠ irrelevance
- truth ≠ relevance
- relevance ≠ authority
- confidence ≠ standing
- standing ≠ warrant
- capability ≠ warrant or authorization
- local phenotype ≠ inherited architecture
- current ≠ newest
- runtime reorientation ≠ constitutional redesign
- operational classification ≠ ontological exhaustion
- operational closure ≠ metaphysical closure

## Universal identity

Every persisted claim, event, artifact, Master-Key expression, envelope, packet, aperture, warrant, evaluation, enforcement rule, and other first-class governance object SHALL possess a stable referent identity.

Type-specific content remains in its native record.

Referent registration does not imply:

- authority;
- standing;
- promotion;
- or ontological significance.

## Enforcement

Every consequential normative requirement SHALL declare:

**MODE**

- STRUCTURAL
- SEMANTIC
- AUTHORITY
- OBSERVATIONAL

and:

**SURFACE**

- schema constraint;
- transaction;
- controller;
- semantic evaluation;
- authorization check;
- runtime observer;
- revalidation mechanism.

A requirement may compose modes.

No consequential transition may depend solely on an agent remembering an instruction.

## Hard stop

If a schema, tool, migration, prompt, or implementation would make one of these distinctions unrecoverable:

**STOP THE BUILD UNIT.**

Do not silently reinterpret the invariant.
